# Документооборот (`@crm-nordiv/docuflow`)

Задания, процессы и документы компании в одном разделе. Ставится в CRM как приложение, без правок
сервера.

- universalIdentifier: `0b7d5d2e-8c4f-4a59-9a43-2f6f1c3e9d21`

## Что получается после установки

| Где | Что |
|---|---|
| Сайдбар | пункт «Документооборот» с вкладками «Задания», «Процессы», «Документы» |
| «Задания» | задачи раздела «Документооборот»; фильтры «Открытые / Мои / Просроченные / Выполненные / Архив» (архив — удалённые, со штатным «Восстановить»), поиск, создание задания с инструкцией и полями для заполнения |
| Карточка задачи | вкладка «Задание»: инструкция, поля задания (собрать конструктором, заполнить), «Выполнить» |
| Карточка процесса | кнопка «Параметры запуска» вверху (боковая панель): параметры запуска (конструктор полей) и, для шагов «Человеческий ввод» черновика, кто выполняет, срок в днях, обязательные поля; у каждого поля видна переменная, которой его читают следующие шаги |
| Редактор процесса | шаг «Параметры запуска» (ставится сам): отдаёт следующим шагам параметры, заполненные перед запуском |
| «Процессы» | процессы с ручным запуском раздела «Документооборот»; форма параметров до запуска, «Запустить», «Создать», «Изменить процесс» |
| «Документы» | папки, фильтры, поиск по названию и номеру, документ с реквизитами (тип, номер, дата, срок действия, контрагент, описание), файл в поле «Файл» карточки, карточка с источником |
| Автоматически | шаг «Человеческий ввод» процесса становится задачей; её выполнение продолжает процесс; файл, приложенный к любой записи, копируется в документы с отметкой, кто, когда и куда его добавил |
| Битрикс24 | страница приложения в портале со списком открытых заданий сотрудника и ссылками в CRM; уведомление исполнителю нового задания |

## Данные

| Объект | Поля |
|---|---|
| `smbDocument` (новый) | название, файл, тип, номер, дата, действует до, контрагент (компания), описание, статус, автор, ответственный, папка; источник: `origin`, `sourceObjectName`, `sourceRecordId`, `sourceRecordName`, `sourceFileId`, `workflowRunId` |
| `smbDocumentFolder` (новый) | название, цвет, родительская папка |
| `workflow` | `smbSection` «Раздел»: CRM / Документооборот; `smbLaunchFields` «Параметры запуска» — поля, которые заполняют перед запуском |
| `task` | `smbSection`, `smbInstruction` «Инструкция»; `smbFormSchema`, `smbFormValues` — поля задания; `smbWorkflowRunId`, `smbWorkflowStepId`, `smbWorkflowThreadId` — связь с шагом процесса |
| `company` | `smbDocuments` — документы контрагента |
| роли | «Документооборот: функции приложения» (права функций), «Документооборот: участник процессов» (для людей, см. ниже) |

## Установка

На сервере, где запущен Twenty, из каталога с его `docker-compose.yml`; повторный запуск
ставит новую версию:

```bash
docker compose exec server npx -y @haiiro/install@latest docuflow
```

Ключи не нужны: установщик работает внутри контейнера сервера и вызывает его команды
`marketplace:catalog-sync`, `application:install` и `application:upgrade`. Приложение ставится
во все компании сервера. Конкретная версия: `docuflow@0.0.6`. Публикация из репозитория форка:
`bash scripts/smb-publish.sh docflow`.

Из исходников (для разработки): `yarn install && yarn app remote:add --url … --api-key … --as prod && yarn app apply --remote prod`.

Затем в «Настройки → Приложения → Документооборот» заполнить переменные:

| Переменная | Что указать |
|---|---|
| `DOCFLOW_ENGINE` | `APP` |
| `CRM_PUBLIC_URL` | адрес CRM компании, например `https://acme.example.ru`; по нему строятся ссылки из Битрикс24 |
| `BITRIX_CLIENT_ID`, `BITRIX_CLIENT_SECRET` | из карточки локального приложения портала; без них Битрикс24 не подключается, остальное работает |

**Права людей.** Отвечать на шаг запущенного процесса может только тот, у кого есть право
«Рабочие процессы». Кто выполняет задания процессов или запускает процессы с параметрами,
получает роль «Документооборот: участник процессов» или это право в своей роли. Право также
позволяет менять процессы: давайте его тем, кому это допустимо. Обычные задания и документы
права «Рабочие процессы» не требуют.

## Как пользоваться

- **Процесс.** «Процессы → Создать» создаёт процесс с ручным запуском в разделе «Документооборот» и
  открывает редактор. Существующий процесс переносится в документооборот полем «Раздел».
- **Параметры запуска.** Кнопка процесса «Параметры запуска» → «Добавить поле»: название, тип
  (текст, число, дата, сотрудник, компания, контакт, сделка), обязательность. «Сохранить параметры»
  ставит процессу ручной запуск, если запуска ещё нет, и сразу после него — шаг «Параметры
  запуска». В следующих шагах параметры выбираются в списке переменных как поля этого шага:
  `{{<шаг>.<поле>}}`, точное имя показано рядом с полем. Опубликуйте процесс. Параметры
  заполняются в «Процессах» до запуска; обязательные проверяются и на странице, и на сервере, а
  значения хранятся в запуске (`trigger.smbDocflowParameters`).
- **Задание шага.** Шаг «Человеческий ввод» становится задачей раздела процесса: у исполнителя
  из «Параметров запуска», без него — у запустившего. Поля задания — поля шага из редактора.
  «Выполнить» проверяет обязательные поля и продолжает процесс; значения дальше читаются
  переменными шага `{{<шаг>.<поле>}}`.
- **Своё задание.** «Задания → Создать»: название, исполнитель, срок, инструкция и поля для
  заполнения тем же конструктором. Поля меняются в панели задания («Изменить поля»).
- **Документы.** «Документы → Создать» создаёт черновик в открытой папке и открывает его штатную
  карточку: там реквизиты и поле «Файл»; строка списка открывает ту же карточку. Так сделано потому, что
  страница приложения в песочнице видит только имя и размер выбранного файла, не его содержимое.
  Файл, приложенный к любой записи (компания, сделка, задача, свой объект), появляется в
  документах сам: «Где загружен», автор, дата, для задачи процесса — ссылка на запуск. Документ
  хранит копию файла.

## Ограничения

- Рамки вокруг страницы раздела рисует платформа: карточку виджета и рамку вокруг компонента
  приложения. Компоненты приложений работают в изолированном worker'е и убрать их не могут.
- Параметры видны в редакторе только как переменные шага «Параметры запуска»: у блока «Запуск
  вручную» Twenty показывает лишь свои переменные, поэтому без шага их не выбрать.
- Параметры запуска относятся к процессу, а не к версии: после правки полей опубликованная версия
  до публикации нового черновика получает новые поля, а переменные убранных полей в ней пусты.
- Если после ручного запуска идут сразу несколько шагов, «Параметры запуска» встаёт перед
  первым из них; остальным ветвям переменные шага недоступны.
- Документ без файла создаётся раньше файла: если закрыть карточку, не прикрепив файл, документ
  останется с пустым полем «Файл».

## Битрикс24

Подключается локальным приложением портала (одна компания — один портал).

1. В портале: «Разработчикам → Другое → Локальное приложение», тип «Серверное».
2. Адреса — HTTP-маршруты приложения на адресе компании (точный адрес виден в «Настройки →
   Приложения → Документооборот → функции»):
   - путь обработчика: `https://<адрес компании>/s/bitrix/app`
   - путь первоначальной установки: `https://<адрес компании>/s/bitrix/install`
3. Права приложения: `user`, `im`.
4. Сохранить, скопировать «Код приложения» и «Ключ приложения» в `BITRIX_CLIENT_ID` и
   `BITRIX_CLIENT_SECRET`, затем открыть приложение в портале — установка завершится сама.

Каждый запрос портала проверяется обменом refresh-токена на `oauth.bitrix.info` с ключом
приложения; адрес портала берётся из ответа Битрикс24. Привязывается первый подтверждённый портал,
другой портал к той же компании не подключится. Токены портала хранятся в хранилище приложения, не
в записях. Сотрудник находится по почте профиля Битрикс24.

## Разработка

```bash
yarn app dev        # следит за src/ и синхронизирует с сервером
yarn app dev:function:logs
yarn test && yarn typecheck && yarn lint
```

Устройство `src/`: `shared/` — общий код (формы, процессы, фильтры REST, Битрикс24); `server/` —
обращения к записям и движку процессов из функций; `logic-functions/`; `front/` и
`front-components/` — интерфейс; `objects/`, `fields/`, `views/`, `roles/`, `page-layouts/`,
`navigation-menu-items/` — данные и раскладка. Записи читаются и пишутся только через REST API
(`server/records.ts`, `front/api.ts`), движок процессов — через две мутации GraphQL
(`server/workflow-engine.ts`, `server/launch-step.ts`): при смене версии платформы сверять эти
файлы. Стили интерфейса только inline: теги `<style>` в странице приложения платформа отбрасывает.
